## 兼容性

- qualification 计划增加必填 `stop_temperature_c`，当前 H1 最大允许 55°C；失败时有 summary 和已采集 CSV。
- qualification 启动记录是 `SIM` 类型，完成才产生 `SIM_PASS`；失败状态不能作为通过证据。
- runtime 新增 `servo_timeout_ms`，旧配置未填写时使用 IMU timeout；安全状态需要关闭并重新初始化。
- Policy Contract 的 normalization 必须有明确 mode；旧非空占位字典不能继续打包。当前模型边界为单 float32、固定 batch=1、静态观测和动作维、自包含文件。
- 评估报告 schema 升为 2，改用逐环境误差指标。原策略、训练日志和历史验证记录保留原版本语义。
- 物理发布包版本升为 1.1.1，六维力矩以关节原点、世界坐标轴表达。纯净回放和策略权重保留，相关分析载荷与哈希同步更新。
- 发布页 HTML/JS 保留原始字节以稳定跨平台 SHA256；发布 CSV 保留生成器的 CRLF，补丁保留空上下文行必需的空格，并显式声明行尾检查规则，不改变载荷内容。

## 依赖与许可证

新增可选 `policy` extra：`onnx>=1.19,<2`，开发依赖组同时包含它以执行真实模型测试；本次锁定 ONNX 1.22.0（Apache-2.0）。传递依赖锁定为 NumPy 2.5.2、ml-dtypes 0.6.0、protobuf 7.36.1、typing-extensions 4.16.0。安装来自现有包管理器，`uv.lock` 固定解析结果。

ONNX / ml-dtypes 为 Apache-2.0；protobuf 为 3-Clause BSD；typing-extensions 为 PSF-2.0；NumPy 已安装元数据列示 BSD-3-Clause、0BSD、MIT、Zlib、CC0-1.0。打包工具在开发机通过 `uv sync --extra policy` 安装；基础项目依赖列表仍为空，runtime/hardware 模块不导入 ONNX。未新增真实硬件驱动依赖。

采用官方库的原因是需要校验 protobuf 图、shape inference 和实际 tensor 类型；文件后缀或自写维度解析不足以完成合同验证。来源：[ONNX checker](https://onnx.ai/onnx/api/checker.html)、[ONNX LICENSE](https://github.com/onnx/onnx/blob/main/LICENSE)。

## 保留的边界

同步控制 API 不抢占正在执行的 I/O，也不以后台线程制造返回后的延迟写入。真实总线接入仍须完成有限超时、最大延迟和硬件 watchdog 的实测。所有本次验证均为软件、SIM 或 mock，不产生 HIL/REAL 通过结论。
