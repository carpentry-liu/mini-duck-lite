# REF-0001：代码审查缺陷修复

日期：2026-09-05。基线：`3ceb4c92`。用户已授权修复审查确认的 12 项问题，并在验证通过后提交、推送。当前仍为 H1；验证只使用 mock、模型文件和仿真。

## 范围与方案

| 范围 | 问题 | 实施方案 |
|---|---|---|
| SafeRuntime | 反馈异常继续驱动、I/O 超时后写旧命令、CLI 假 PASS | 先读取并校验全组反馈，再逐次检查期限后写入；安全状态锁存；结果与退出码反映运行成功率 |
| IMU | BNO055 四元数顺序错误 | 按驱动原生 wxyz 保留顺序，用已知姿态回归验证 |
| qualification | 缺少 55°C 停止、采样时钟不一致 | 配置停止阈值；异常时停止动作并归档失败；单调绝对时刻调度，mock 支持一致虚拟时钟 |
| policy bundle | 未读 ONNX 图、normalizer 弱校验 | 使用官方 ONNX 解析和检查能力；验证输入输出形状和合同；明确归一化模式及数值约束 |
| manifest | 未测电流、非有限软限位错误放行 | 实测状态与有限正数联合判定；校验有限有序软限位和有效 bus ID |
| 步态验收 | 环境间偏差抵消、非零偏航误拒绝 | 逐环境累计相对目标的时间净误差，再统计绝对误差；保留单环境周期摆动的允许语义 |
| 物理发布包 | 空间力矩参考点错误 | 将 COM frame 力矩平移到关节 anchor，明确原点/轴向；更新发布补丁、相关数据与展示材料及哈希 |

比较过两种实施方式：只修校验条件并保留旧证据，或把公共契约、生产路径、回归测试和受影响的发布数据一起修正。采用后者，避免源码已修而发布文件仍展示旧语义。对物理字段也可只改名为原始 COM 力矩，但本项目当前产品承诺是关节六维力矩，因此优先真正换算到关节原点。

ONNX 校验优先复用官方库，不实现私有 protobuf 解析。打包依赖应按可选工具依赖隔离，避免给 mock/hard loop 强加加载；具体版本、许可证和安装影响在实施记录补齐。

## 非目标与边界

- 不接真实舵机、不执行 HIL/REAL、不改变 H1 Gate，不实现完整 ONNX 推理 provider。
- 不训练新策略、不修改策略权重，不修改外置 `_upstream` 的现有工作树。
- 上游补丁验证和重放在隔离副本或 worktree 中完成，来源、基线和修改范围继续可追溯。
- 不使用后台线程强行取消未知阻塞 I/O；backend 必须提供有界 I/O，运行时在每次写入前检查剩余预算，明确真实 backend 的准入要求。

## 验证与回滚

回归覆盖审查中的 12 个触发例，并覆盖有效合同、正常 runtime、正常 50 Hz mock 测试和正常步态验收。运行仓库最小检查、构建、发布哈希校验和补丁顺序应用；涉及展示变更时检查真实页面、截图和控制台。每项实际命令和结果写入 `03-验证.md`。

按模块提交可独立审查的修复；所有验证完成后推送当前 `main`。回滚使用对应提交的 revert，保留旧 Git 历史及原策略权重。
